# Tolerance Workspace — Audit Package Comparison & Change Impact

## Purpose

The Audit Comparison surface exposes the Stage 15P (audit comparison) and Stage 15Q
(change impact) capabilities through the tolerance workspace UI. It allows an engineer to
compare two deterministic audit packages and assess the engineering significance of any
differences, without leaving the workspace.

**Audit comparison identifies deterministic differences between audit packages. Change
Impact evaluates those differences using the Stage 15 engineering backend. Neither
represents approval, disposition, certification, or autonomous engineering judgment.**

## Explicit Workflow

1. Engineer completes the full audit workflow: analysis → decision → evidence → report →
   audit package (`run_audit_package()`). This becomes the **reference package**.
2. Engineer loads a candidate audit package from a JSON file:
   **Load Comparison Package** → `load_comparison_audit_package(path)`.
3. Engineer clicks **Compare Audit Packages** → `run_audit_comparison()` → Stage 15P
   comparison result cached as `_last_audit_comparison`.
4. Engineer clicks **Evaluate Change Impact** → `run_change_impact()` → Stage 15Q impact
   result cached as `_last_change_impact`.

## Stage 15 Authority

Audit comparison is produced exclusively by the Stage 15P engine function:

```
compare_decision_audit_packages(
    baseline: ToleranceDecisionAuditPackage,
    candidate: ToleranceDecisionAuditPackage,
) → AuditPackageComparisonResult
```

Change impact assessment is produced exclusively by the Stage 15Q engine function:

```
assess_audit_change_impact(
    comparison_result: AuditPackageComparisonResult,
) → AuditChangeImpactResult
```

The workspace controller, session, and UI are consumers only. They do not recompute
differences, duplicate hash comparisons, fabricate impact classifications, or reinterpret
audit meaning.

## Second Package Input Contract

The comparison package is loaded from a JSON file on disk. The file must contain a
valid, verifiable `ToleranceDecisionAuditPackage` serialized by Stage 15O. Loading
delegates all deserialization and verification to `audit_package_from_dict(..., verify=True)`.

Loading fails closed for:
- Non-JSON content
- JSON that is not an object (e.g. an array)
- Missing or malformed required fields
- Package ID mismatch (tampered payload)
- Fingerprint mismatch
- Replayability status mismatch

No fingerprint or hashing logic is duplicated in the workspace controller.

## Current Package Source

The **reference package** is always `_last_audit_package` (the package generated by the
most recent `run_audit_package()` call in this workspace session). The reference package
is the baseline in the Stage 15P comparison call.

## Prerequisites

`run_audit_comparison()` requires:

- `_last_audit_package` must not be `None` (raised: "Generate Audit Package first.")
- `_comparison_audit_package` must not be `None` (raised: "Load Comparison Package first.")

`run_change_impact()` requires:

- `_last_audit_comparison` must not be `None` (raised: "Run Audit Comparison first.")

No other preconditions are checked; all calls are fail-closed.

## Runtime-Only State

The following fields are **never persisted** to the workspace schema or project file:

| Field | Set by | Cleared by |
|---|---|---|
| `_comparison_audit_package` | `load_comparison_audit_package()` | Never (stays until explicitly replaced) |
| `_last_audit_comparison` | `run_audit_comparison()` | Any upstream change (see Stale Clearing) |
| `_last_change_impact` | `run_change_impact()` | Any upstream change or comparison regeneration |

- `save_project` / `open_project`: comparison state not saved; restored controller has all
  three fields as `None`.
- `from_state`: comparison state not included; restored controller clears all three.
- Comparison must be re-run after every session load.

## Stale Clearing

`_last_audit_comparison` and `_last_change_impact` are cleared (set to `None`) whenever
the reference package (`_last_audit_package`) becomes stale or is replaced:

- `set_chain_name()`
- `set_analysis_mode()`
- `set_specification()`
- `run_analysis()`
- `evaluate_decision()`
- `run_decision_evidence()`
- `run_decision_report()`
- `run_audit_integrity()`
- `run_audit_package()` (new package replaces old reference)
- `_replace_contributors()`
- `from_state()`

`_last_change_impact` is additionally cleared when:
- `run_audit_comparison()` generates a new comparison result.
- `load_comparison_audit_package()` loads a new candidate package.

`_comparison_audit_package` is **not** cleared by upstream changes — it is an external
input that persists until explicitly replaced by a new `load_comparison_audit_package()`
call.

## Persistence Boundary

```
WorkspaceProject (persisted JSON)
  └── chain_name, analysis_mode, contributors, specification
  └── allocation_plan, statistical_allocation_plan
  ← last_result, last_decision, last_sensitivity, last_budget,
     last_reconciliation, last_statistical_reconciliation  (runtime)
  ← last_evidence, last_explanation  (runtime — Stage 20B)
  ← last_decision_report  (runtime — Stage 20C)
  ← last_audit_integrity, last_audit_package  (runtime — Stage 20D)
  ← comparison_audit_package, last_audit_comparison, last_change_impact
     (runtime — Stage 20E)
```

## Identity Boundary

`load_comparison_audit_package()`, `run_audit_comparison()`, and `run_change_impact()`
do not touch `configuration_fingerprint()` (which hashes `WorkspaceState` only). No
schema version increment. No comparison or change-impact fields added to workspace
identity.

## Feature Isolation

The comparison surface is fully isolated. Loading a comparison package, running a
comparison, or evaluating change impact has no side-effects on any other workspace
feature. All other features (sensitivity, budget, allocation, reconciliation, audit
integrity, audit package) are unaffected.

## UI Presentation

**Audit Package Comparison** section (workspace row 16):
- **Load Comparison Package** button: file dialog → `load_comparison_audit_package(path)`
  → refreshes comparison display.
- **Reference Package** label: first 16 hex chars of the reference package ID.
- **Comparison Package** label: first 16 hex chars of the comparison package ID (or
  "NOT LOADED").
- **Compare Audit Packages** button: calls `run_audit_comparison()`.
- **Status** label: comparison status (IDENTICAL / CHANGED / INCOMPATIBLE) or
  "NOT COMPARED".
- **Changes** treeview: columns significance, category, code, scope, subject_id, detail.
  Populated from `audit_comparison_changes_rows()`. Empty for IDENTICAL.

**Change Impact** section (workspace row 17):
- **Evaluate Change Impact** button: calls `run_change_impact()`.
- **Status** label: overall impact level or "NOT EVALUATED".
- **Impact** treeview: columns impact, reason, code, category, scope, detail.
  Populated from `change_impact_rows()`. Empty when no assessed changes.

## Non-Goals

The comparison surface explicitly does NOT:

- Implement change disposition or approval workflow.
- Implement approval readiness assessment.
- Implement governed acceptance or acceptance verification.
- Export comparison results to HTML or PDF.
- Add AI-generated comparison commentary.
- Certify, approve, or reject an engineering design.
- Persist comparison state to disk.
- Serve as the engineering authority for tolerance calculations.
- Auto-generate missing prerequisite objects.
- Independently compute package fingerprints or impact severity.
