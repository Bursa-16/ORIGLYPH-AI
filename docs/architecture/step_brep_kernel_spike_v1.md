# STEP/B-Rep Kernel Feasibility Spike v1 (Stage 22D)

> **This stage is a technical feasibility spike and does not constitute
> production STEP support.**
>
> **Canonical snapshot identifiers do not solve persistent topology naming
> across CAD revisions.**
>
> **No STEP/B-Rep topology is persisted into the Origlyph project model in
> Stage 22D.**

---

## Goal

Prove that a STEP file can be read via a Python B-Rep kernel, its topology
traversed hierarchically, and the result represented exclusively through
Origlyph's Stage 22C `CanonicalTopologyModel` without leaking kernel objects
into the domain model.

### Why cadquery-ocp-novtk

- PyPI binary wheels for Windows amd64 (Python 3.10–3.14 confirmed).
- No VTK / visualization dependency (smaller than full `cadquery-ocp`).
- Gives direct access to low-level OpenCASCADE APIs: `STEPControl_Reader`,
  `TopExp_Explorer`, `TopoDS_Iterator`, `BRep_Tool`, `BRepTools`, etc.
- No high-level CadQuery/build123d scripting surface area — cleaner adapter
  isolation.
- Active maintenance by the CadQuery core team.

### OCCT Relationship

`cadquery-ocp-novtk` is a thin pybind11 wrapper over OpenCASCADE Technology
(OCCT), an open-source geometric modelling kernel originally developed by
Matra Datavision, now maintained by Open Cascade SAS and the community.

## Runtime Environment

Origlyph's default runtime (Python 3.10+ on any OS) does **not** require
cadquery-ocp-novtk. The `StepKernelAdapter` raises `StepKernelUnavailableError`
immediately if OCP is absent at runtime, with a clear error message. This
fail-closed pattern is enforced at every entry point.

---

## Adapter Boundary

```
STEP file (disk)
    │
    ▼  STEPControl_Reader (OCP)
  OCC shape (TopoDS_Compound / TopoDS_Solid)
    │
    ▼  _build_canonical() — all OCP objects consumed here
  CanonicalTopologyModel (Origlyph domain)
    │
    ▼  callers — zero OCP objects visible
```

`StepKernelAdapter` implements the Stage 22C `CadTopologyAdapter` protocol.
No OCP type appears in any return value, exception message, topology entity,
geometry value, or identity field.

The module-level `_ocp_available()` function uses `importlib.util.find_spec`
to detect OCP at runtime without triggering an import.  All OCP imports are
local to the two conversion functions so that importing
`origlyph.cad.step_kernel_adapter` never fails regardless of whether OCP
is installed.

## STEP Import Proof

**Fixture:** `tests/fixtures/cad/simple_box.step` — a 10 × 20 × 30 mm
rectangular solid, generated by OCP's `BRepPrimAPI_MakeBox` and
`STEPControl_Writer`, with the FILE_NAME timestamp replaced by a fixed value
for determinism.

**Counts from actual import:**

| Entity | Canonical count |
|---|---|
| Solids (bodies) | 1 |
| Shells | 1 |
| Faces | 6 |
| Wires | 6 |
| Edges | 12 (deduplicated) |
| Vertices | 8 (deduplicated) |

Edge deduplication uses `IsSame()` (OCC shape identity comparison on the
underlying TShape pointer), which correctly identifies the 12 unique edges
from the 24 oriented-edge occurrences in the 6 wires. Vertex deduplication
similarly collapses 48 vertex occurrences to 8 unique vertices.

---

## B-Rep Traversal

Traversal is strictly hierarchical via `TopoDS_Iterator`:

```
Solid → Shell(s) → Face(s) → Wire(s) → Edge(s) → Vertex pair
```

No flat count trick. Each level's `TopoDS_Iterator` yields direct children only.
`BRepTools.OuterWire_s()` distinguishes the outer wire from inner hole wires on
each face; a fallback (first wire = outer) handles the common case where the
match via `IsSame` does not trigger.

Vertex coordinates are extracted via `BRep_Tool.Pnt_s()` on each
`TopoDS_Vertex`, yielding `(X, Y, Z)` floats mapped directly to
`origlyph.geometry.Point3D`.

## Unit Handling

**STEP_UNIT_HANDLING: KNOWN**

OpenCASCADE reads the `LENGTH_UNIT` declaration from the STEP file header and
converts all coordinates to its internal unit (millimeters, confirmed by
`UnitsMethods.GetCasCadeLengthUnit_s() == 1.0`). Vertex coordinates returned by
`BRep_Tool.Pnt_s()` are therefore always in **millimeters**, regardless of the
source STEP file's declared unit (mm, inch, etc.).

Consequence: the `SourceUnitSystem` in the returned `CanonicalTopologyModel`
should declare `length_unit="mm"`. Origlyph callers must not silently assume any
other unit. If the source STEP file declared a non-mm unit, OCC silently converts;
the original unit declaration is not currently surfaced through this spike adapter.

For controlled production integration, the original STEP unit should be read from
the XCAF/XDE layer and recorded in `SourceDocumentIdentity`. This is not
implemented in Stage 22D.

## Deterministic Snapshot ID Strategy

Entity IDs use traversal-order numbering within each kind:

```
vertex:  v:0001 … v:0008
edge:    e:0001 … e:0012
wire:    w:0001 … w:0006
face:    f:0001 … f:0006
shell:   s:0001
solid:   b:0001
```

**Within the same STEP file:** OCC's shape tree is deterministic (immutable
TShape DAG). Three repeated imports of `simple_box.step` produce bit-for-bit
identical entity IDs, vertex coordinates, and adjacency structure (confirmed by
test `test_snapshot_identity_deterministic`).

**Forbidden ID sources (enforced):** `id()`, `hash()`, kernel pointer string,
`uuid4`, `time.*`, hostname, absolute file path.

**NOT solved:** Persistent naming across CAD revisions. If the source CAD file
is revised (a face split, edge added, etc.), the traversal order changes and IDs
reassign. This is an intentional, documented limitation of Stage 22D.

## Geometry Limitations

| Binding | Status | Notes |
|---|---|---|
| Vertex → `Point3D` | **BOUND** | Full XYZ coordinates via `BRep_Tool.Pnt_s()` |
| Edge → curve | **OPAQUE** | No curve math implemented in spike |
| Face → surface | **OPAQUE** | No surface math implemented in spike |
| NURBS | **NOT SUPPORTED** | Requires curve/surface extraction in a later stage |

Marking edges and faces as OPAQUE is intentional: implementing incorrect or
incomplete curve/surface math would introduce silent geometric errors into the
topology model. The spike proves connectivity without fabricating unsupported
geometry.

## Provenance

The `CanonicalTopologyModel.source` field is set to the
`SourceDocumentIdentity` passed to `to_canonical_topology()`. Callers are
responsible for supplying:

- `source_id`: a stable logical identifier for the STEP document
- `format = CadFormat.STEP`
- `unit_system = SourceUnitSystem(length_unit="mm", ...)` (OCC delivers mm)
- `original_filename`: optional, for traceability

No absolute local path is embedded in entity IDs or in `SourceDocumentIdentity`
fields. OCC source-entity metadata (STEP entity labels via XCAF/XDE) is not
surfaced in this spike; topology entity `source_identity` fields are `None`
throughout.

## Kernel Object Isolation

After `to_canonical_topology()` returns, no live OCC handle exists in the
returned model. This is verified by test `test_no_ocp_objects_in_vertices`
and `test_no_ocp_objects_in_edges`, which inspect `type(x).__module__` on
all stored values. Explicitly verified entities: `TopologyVertex.point.x/y/z`
(pure Python `float`), `TopologyEntityId.value` (pure Python `str`),
`TopologyEdge.start_vertex_id` / `end_vertex_id` (pure Python `TopologyEntityId`).

A forced garbage collection in `test_model_survives_without_kernel_handles`
confirms the returned model remains fully traversable after any lingering OCC
objects are released.

## Failure Modes

All failures are fail-closed (`CadImportError` or `StepKernelUnavailableError`).
No silent fallback to empty successful topology.

| Scenario | Behaviour |
|---|---|
| OCP not installed | `StepKernelUnavailableError` at first adapter call |
| File not found | `CadImportError("STEP file not found")` |
| Malformed content | `CadImportError` (IFSelect status ≠ RetDone) |
| Empty file | `CadImportError` (zero transferable roots) |
| No solid body | `CadImportError` ("contains no solid bodies") |
| Null shape after transfer | `CadImportError` ("produced a null shape") |
| Degenerate edge (<2 vertices) | `CadImportError` |
| Degenerate wire (no edges) | `CadImportError` |
| Degenerate shell (no faces) | `CadImportError` |
| Degenerate solid (no shells) | `CadImportError` |
| Duplicate canonical IDs | `DuplicateTopologyIdError` (raised by `CanonicalTopologyModel`) |
| Dangling reference | `DanglingTopologyReferenceError` (raised by `CanonicalTopologyModel`) |

## Production Registration

`StepKernelAdapter` is **not** registered in Origlyph's production CAD importer
dispatch. `.step`/`.stp` file extensions do not appear in any format registry,
UI filter, or `CadImporter` configuration. The class is not exported from
`origlyph.cad.__init__`. This is enforced by tests `test_step_not_in_production_format_registry`
and `test_step_kernel_adapter_not_in_cad_all`.

For Stage 22E controlled integration, the recommended approach is to add

capability installable with `pip install origlyph[brep]`.

## Limitations

1. **No production STEP support.** CadFormat.STEP exists in the enum but no
   production import path dispatches to this adapter.
2. **Persistent topology naming not solved.** IDs are stable within one import
   session but reassign when the source CAD file is revised.
3. **Edge and face geometry is opaque.** Curve and surface types are not bound
   to Origlyph geometry contracts in this spike.
4. **Source STEP unit not surfaced.** OCC converts to mm silently; the original
   unit declaration is not read from XCAF/XDE.
5. **Open shells not supported.** Only `TopAbs_SOLID` shapes are traversed; a
   pure-shell STEP file raises `CadImportError`.
6. **Large assemblies untested.** The spike uses a minimal synthetic fixture only.
7. **No STEP entity metadata.** Topology entity `source_identity` fields are
   `None`; XCAF label mapping is not implemented.
